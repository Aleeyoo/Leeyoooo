### Article: 日更长文的秘密：我用爬虫搭了一个内容工厂

我在 X 上日更长文，写文章本身不是最花时间的环节。真正吃掉时间的是写之前的事——搜选题至少半天，收集素材至少两小时，验证每个数字的来源又要一小时。直到我把这些全交给了爬虫，写之前的准备时间从四五小时压缩到了不到一小时。

这两天我写了两篇长文。第一篇是 AI 投毒行业拆解，写之前我用爬虫从央视 315 晚会、36 氪、证券时报、消费者报道等 8 个来源抓了原文，逐篇提取关键数字和可引用的段落，存成一个按来源分类的素材包。第二篇是 Claude Code 非程序员攻略，写之前我用爬虫搜了 210 多条过去两个月在 X、知乎、Reddit 上发布的相关内容，从里面找到了这个选题，然后抓了 5 篇英文深度长文和 50 多条中文帖子做素材。

两篇文章的调研加起来花了不到 1 小时。如果手动做——逐个打开网页、复制粘贴、整理到文档——我估计至少两天。

这篇文章不是一份工具说明书。我想讲的是一个更具体的事情：一个日更长文的人，怎么把爬虫变成自己内容生产系统的底层数据引擎。我用的工具是 XCrawl，一个通过 API 或 MCP 接入的网页抓取服务。下面所有的操作和数据都是真实的，截图来自我自己的工作目录。

## 内容创作者的隐性瓶颈不是写，是找

做内容的人大概都有过这种体验：花了一整天在各种网站上搜资料、复制粘贴、整理成文档，结果真正动笔写的时间只有最后两个小时。

写一篇 3000 字的长文，AI 可以帮你出初稿，人工修改打磨一两个小时差不多了。但写之前的事情远比这复杂：你要先知道这个话题别人已经写过什么，你要找到足够多的数据和案例来支撑你的判断，你要确保引用的每个数字都能追溯到一手来源，你还要从海量信息中筛选出真正对这篇文章有用的素材。

这些事情占据了内容生产的绝大部分时间，而且每篇文章都要重来一遍。选题要重新搜、素材要重新找、数据要重新验证。更要命的是，这些工作的本质是机械的重复劳动——打开一个网页、找到关键信息、复制到文档、打开下一个网页。

爬虫解决的就是这个环节。它不帮你写文章，它帮你把写文章之前的数据搬运工作自动化。

## 选题：从 200 条爆文里找到值得写的话题

我在自己的内容系统里建了一套叫「选题雷达」的工作流。核心逻辑很简单：过去两个月在 X、知乎、公众号上爆过的内容，说明这个话题有需求。热度已经回落意味着竞争也在减少。翻写一个已经被验证过的选题，比从零创造一个新选题成功率高得多。

具体操作是这样的：我提前设计好 10-15 组搜索关键词，覆盖不同的话题方向和表达方式。比如我这次找的是 AI 教程和 AI 赚钱方向的选题，关键词组合包括「AI 工具 赚钱」「Claude Code 教程」「一个人 AI 创业 月入」「AI 副业 变现」「AI 自动化 工作流」「Vibe Coding 赚钱」等等。每组关键词都带上时间过滤，只搜两三个月前的内容。

然后把这些关键词丢给 XCrawl 的 Search API。每组搜索返回 15 条结果，包含标题、摘要和链接。10-15 组搜索跑下来，总共拿到 150-200 条内容。

![Article Image](<https://pbs.twimg.com/media/HI5OBvLaIAE8zX-.jpg>)

拿到这些数据之后，关键步骤是聚类。我不会逐条去看 200 条内容的全文，而是看标题和摘要就够了——如果同一个话题被 3 个以上不同的账号写过，并且都有不错的互动数据，这就是一个已经被市场验证过的强需求。

这次扫描的结果是识别出了 8 个母题：Claude Code 不只是写代码（出现 10+ 次）、AI 工具全家桶（10+ 次）、AI 自动化工作流实战（6+ 次）、Vibe Coding 赚钱真相（8+ 次）、AI 副业真实收入（8+ 次）。每个母题下面都挂着一批具体的爆文链接，任何一个展开都是一篇值得写的文章。

我最终选了「Claude Code 非程序员指南」这个方向，因为它满足三个条件：我自己每天在用（有一手经验）、这个角度在中文内容里还没有一篇足够完整的（有翻写空间）、它是教程类内容（天然适合被收藏）。

整个选题过程大约 30 分钟，消耗了约 60 个 XCrawl credits。如果没有爬虫，这 200 条内容我要一条一条去搜、去翻、去判断，至少要花半天。

## 素材抓取：把参考文章变成结构化素材包

选题定了之后，下一步是收集素材。

写 Claude Code 那篇文章时，我需要尽可能多地了解别人已经怎么写这个话题了——哪些角度被覆盖过、哪些案例被引用过、哪些说法有数据支持。中文内容里有 @shao\_meng 的 X 帖子（75,900 views，706 bookmarks）、@orange 和 @Gorden\_Sun 的教程帖、知乎上十几篇相关文章。英文内容里有一篇前 Google 首席科学家 Waleed Kadous 写的深度 Medium 文章、一篇 Prompt Warrior 的 5 个用法拆解、一个 Reddit 社区讨论帖、一篇 Department of Product 的 Substack 文章。

我做的事情：把这些 URL 整理成一个列表，用 XCrawl 的 Scrape API 逐篇抓取。每篇输出 Markdown 格式的正文，包含元数据（作者、发布日期、互动数据）。抓回来之后直接存到 vault 的创作目录里，每篇一个文件，文件名标注来源。

![Article Image](<https://pbs.twimg.com/media/HI5OFT3a8AA8RKy.png>)

写 AI 投毒那篇的时候也是同样的流程，但来源更复杂。央视 315 晚会的报道、36 氪的深度调查、证券时报的记者实测、消费者报道的暗访实录、搜狐和野马财经的独立报道——我总共抓了 14 篇来源，每篇提取了标题、核心数据、关键引述、发布日期。

这个环节最重要的不是「抓网页」这个动作本身，而是输出格式。XCrawl 返回的是干净的 Markdown，不是一堆带广告和导航栏的 HTML。这意味着我拿到的每篇素材可以直接丢给 Claude Code 读——它读 Markdown 和读本地文件一样顺畅，不需要我手动清洗。

一个经常被低估的细节：X 的帖子用普通浏览器复制粘贴的话，只能拿到纯文本，格式全丢。但 XCrawl 支持 JS 动态渲染，能把 X 帖子的完整内容（包括 og:title 里经常藏着的长文正文）完整抓下来。知乎文章也是一样，很多正文内容是 JavaScript 动态加载的，不渲染就拿不到完整内容。

两篇文章的素材抓取总共消耗了大约 80 个 credits。时间上，从列出 URL 列表到所有素材落入 vault，大概 15 分钟。

## 行业调研：从零扫描一个行业只要 5 分钟

写文章之外，爬虫另一个高频用途是行业调研。我用一个刚做的例子来展示完整流程。

假设我现在想快速了解 AI 视频生成工具的市场格局——哪些产品在领跑、各自的定位和定价是什么、用户的真实评价如何。如果手动做这件事，需要在 Google 上搜一圈、逐篇打开对比文章、记下关键信息、再去各家官网找定价页面，大概要花半天。

用 XCrawl 的流程是三步。

第一步，Search：搜关键词找到所有相关的深度对比文章。

我搜了「AI video generation tools comparison 2026 best Sora Runway Kling」，限定时间范围为最近三个月。返回 10 条结果，包括 Reddit 社区讨论、invideo.io 的横评、OpenCreator 的 6 模型对比、YouTube 的排名视频、多个独立博客的测评。

![Article Image](<https://pbs.twimg.com/media/HI5OQ_9a8AAiwzb.jpg>)

第二步，Scrape：抓取最有价值的那篇文章的完整内容。

我选了 OpenCreator 的那篇 6 模型对比（Seedance / Veo / Sora / Wan / Kling / Vidu），用 Scrape 抓了完整正文。拿到的是干净的 Markdown，3000 多词，包含每个模型的优缺点、适用场景和一张决策总结表：想出单用 Veo 3.1，想真实感用 Sora 2，想运镜控制用 Seedance，想做故事用 Wan 2.6，想做 IP 用 Kling 2.6，想省钱铺量用 Vidu Q2。

![Article Image](<https://pbs.twimg.com/media/HI5OUGQacAAnKrs.jpg>)

第三步，Map：扫描竞品站点的全部内容结构。

我想看看 invideo.io（AI 视频工具赛道的头部玩家）到底在博客上写了多少内容、覆盖了哪些话题。用 Map API 扫描它的域名，过滤只看 blog 路径下的 URL，一次性拿到了 30 篇文章的完整列表：从「how to make AI videos」到「best AI video generators」到「TikTok video advertising」到「Instagram Reels 教程」。

![Article Image](<https://pbs.twimg.com/media/HI5OW_VaIAAi25m.jpg>)

这份 URL 列表的价值不只是「知道他们写了什么」。更重要的是它能告诉你竞品没有覆盖什么——那些空白位置就是你的差异化机会。

三步全部加起来：3 次 API 调用，4 个 credits，不到 5 分钟。产出是一份包含市场格局概览、6 款产品优劣对比、竞品内容地图的行业快照。如果我要写一篇 AI 视频工具的推荐文章，这份调研足够支撑全部核心内容。

## 事实核查：交叉验证每一个关键数字

这是整个流程里最容易被忽略但最重要的一步。

AI 投毒那篇文章里有大量具体数字：399 元/年的工具价格、2999 元/季的代运营报价、手机品牌 AI 推荐率从 5% 飙升到 95%、家居品牌获客成本降低 35%、315 晚会曝光的公司一年服务了 200 多个客户。这些数字全部来自不同的来源，每一个都需要确认是否准确、是否来自一手信息、不同来源之间的数字是否矛盾。

核查方式很直接：对每个关键声明，用 XCrawl 的 Search API 搜原始出处。

举一个实际的例子。我的初稿里写的是「2025 年 315 晚会曝光了这条产业链」。核查时我搜了野马财经的原文，发现它的发表日期是 2026 年 3 月 16 日——也就是 315 晚会的第二天。这说明 315 晚会是 2026 年的，不是 2025 年的。如果这个错误没有被核查就发出去，被读者抓到就是一个硬伤。

Search API 有一个特别好用的功能：时间范围过滤。你可以指定只搜 2026 年 3 月 1 日到 3 月 31 日的内容，这样返回的结果高度精准，不会被其他时间段的相似内容干扰。

这个环节每篇文章大约消耗 10-20 个 credits，时间在 10 分钟左右。看起来不多，但它避免的是事实错误——对一个靠信息准确度吃饭的内容创作者来说，这比省时间更重要。

## 整套数据引擎的成本

我的 XCrawl 套餐是 Hobby Plan，月度总额 5000 credits。这两天做了上面所有的调研——两篇文章的素材抓取、一次完整的选题雷达扫描、一次 AI 视频工具行业调研——总共用了大约 560 credits，占月度额度的 11%。

![Article Image](<https://pbs.twimg.com/media/HI5OcjiaIAAEkKz.png>)

拆开来看每个环节的消耗：

选题雷达一次完整扫描：14 组搜索 × 约 4 credits = 约 60 credits 一篇文章的素材抓取（5-15 篇原文）：约 30-50 credits 一次行业调研（Search + Scrape + Map 组合）：约 100-200 credits 事实核查（按需搜索）：约 10-20 credits/篇

一个月写 8-10 篇长文的话，数据采集总消耗大约在 600-800 credits，远低于月度 5000 的额度。

换一个角度算：如果不用爬虫，手动做同样质量的调研，每篇文章至少多花 2-3 小时。一个月 8 篇就是 20 多个小时。这 20 多个小时的时间成本，和 XCrawl 一个月的费用相比，答案很明显。

另一个对比：自己搭爬虫。维护代理池、处理反爬策略变更、写解析脚本、处理各种格式——这些技术成本远超一个 API 的订阅费。我以前试过自己写 Playwright 脚本抓 X 的内容，隔一阵子反爬策略一变，脚本就废了。XCrawl 的反爬由它自己维护，内置住宅代理池和智能指纹，我这边不用操心。

## 不只是写文章

上面讲的是内容创作场景。但同一套数据引擎稍微调整一下方向，还能做别的。

SEO 监控：定期用 Search API 搜自己的目标关键词，看自己的内容在搜索结果里排第几，竞品的内容在什么位置。我的出海站就是这么做 SEO 追踪的。

竞品内容追踪：用 Map API 先扫描竞品博客或内容站的全部 URL 结构，记下有多少篇文章。过一段时间再扫一次，新增的 URL 就是他们最近发的内容，用 Scrape 抓回来就知道他们在写什么。

行业报告生产：这其实是可以卖钱的。抓公开数据 → AI 整理成结构化报告 → 输出 PDF。前面那个 AI 视频工具调研如果包装一下，加上定价分析和市场判断，市场上类似的行业快报卖 500-5000 元一份。

社交媒体监控：搜特定话题在 X 或 Reddit 上的最新讨论，做舆情追踪或者找内容灵感。我的选题雷达本质上就是一种社交媒体监控。

这些场景的共同点是：数据来源是公开的网页内容，需要做的事情是定期采集、结构化整理、喂给 AI 分析。XCrawl 处理「采集」这一步，AI 处理「分析」这一步，中间不需要额外的工具或人工清洗。

## 怎么配置

三种接入方式，选一个就行。

方式 A：MCP 接入（我在用的方式，推荐）

如果你用 Claude Code，一行命令搞定：

claude mcp add xcrawl --url https://mcp.xcrawl.com/{你的API\_KEY}/mcp

配置完之后，你在 Claude Code 里说「用 xcrawl 搜一下最近的 AI 编程工具热门文章」，它就直接去搜了。和聊天一样自然。

Cursor、VS Code、Claude Desktop、Windsurf 也都支持 MCP 接入，配置方式大同小异，都是在设置里加一段 JSON。

方式 B：OpenClaw Skill

在 OpenClaw 命令行说一句：「帮我安装 xcrawl 这个 skill，GitHub 链接：https://github.com/xcrawl-api/xcrawl-skills」

安装后自动集成 4 个组件：scrape、map、crawl、search，直接用自然语言调用。

方式 C：直接调 API

标准 REST API，Python 几行代码就能跑起来。适合要做定时任务或者批量处理的场景。

## 爬虫不是技术，是基础设施

内容工厂的生产流程有两个核心环节：数据采集和内容加工。过去一年 AI 在加工端的进步有目共睹——Claude Code 能帮你写初稿、做诊断、生成标题、设计封面。但采集端很多人还在手动搞，一个网页一个网页地打开、复制、粘贴。

爬虫解决的是采集端的问题。你不需要自己写爬虫脚本、自己维护代理池、自己处理各个网站的反爬策略。就像你不会自己发电，你用电网。数据采集也一样，用一个 API 就够了。
