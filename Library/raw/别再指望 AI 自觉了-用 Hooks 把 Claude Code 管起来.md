# X 上的 码良：“别再指望 AI 自觉了：用 Hooks 把 Claude Code 管起来” / X

https://x.com/cxjwin/status/2058725874921545782?s=20

> 从一个刘海小动画,聊到 Claude Code 的 hooks 机制,再到 claude-mem 是怎么"记住"你的。

## 一、先说人话:什么是钩子

我最早接触 hooks 这个词,是在 Git 里。比如 **.git/hooks/pre-commit**,提交前自动跑一遍格式化。当时只觉得"挺方便",没多想。

直到去年开始重度用 Claude Code,有一天我心血来潮翻文档,翻到 hooks 那一节愣了半天。

这玩意儿,原来才是把 AI 真正"管住"的核心机制。

我才意识到,自己之前所有跟 AI 协作的"约定",都是建立在它"听话"的假设上的。

按我自己理解的话先总结下:

**hook(钩子)就是预先挂在某个"位置"的一段动作。程序走到那里,这段动作就自动执行,不依赖它"记得"要做。**

举个例子:我家楼道里有那种感应灯。我不用记得按开关,人走到那个位置,灯自动就亮了。开关一直挂在那儿,等我经过,到点触发。

再举个例子:网购的包裹一到驿站,我手机"叮"地收到一条短信。这条短信不是驿站员看我顺眼才发的,是系统规则:**包裹一到,必发短信,无条件,不商量**。哪怕驿站员当时在打瞌睡,短信照样发出去。

这两个画面放在一起,hook 的味道就出来了:

- 像感应灯 —— **自动触发,不靠谁记得**;
- 像快递短信 —— **只要那个事件发生了,就必然执行**。

为什么要专门搞这么个机制?因为现在我们用的这堆 AI coding agent(Claude Code、Codex、Cursor 这些),已经不只是"回答问题"了。它会读文件、改代码、跑 Bash 命令、调用各种工具;但它决定下一步干什么,逻辑根本上还是"理解你的话"。

你在 CLAUDE.md 里写一句"改完代码记得跑测试",它**大概率**会照做。

问题就出在"大概率"这三个字上。放在一个跑一周就扔的实验项目里,问题不大;放在公司核心仓库里,就是事故的来源。它今天听话,明天可能就忘了,或者理解偏了。你还不一定能复现。

prompt 是软约束,是"我希望你这么做"。 hook 是比 prompt 更硬的执行约束,是"你做这件事的时候,这段检查或动作会自动发生"。

我后来真正开始重视 hook,就是因为这个:**它能把一部分"靠 AI 自觉"的事,变成"由系统自动触发"的事。**

## 二、一个一眼就懂的例子:刘海里的小动画

光说概念太干,我给你看个特别直观的东西。

GitHub 上有个开源项目叫 CodeIsland。它干的事是:把你 MacBook 刘海那块地方利用起来,实时显示你的 AI 助手现在在干嘛。Claude 正在跑任务、在等你点"同意"、还是已经干完活了,全用像素风的小动画展示出来。你不用再切窗口去瞄一眼终端,余光一扫刘海就知道了。它现在已经支持十多个工具(Claude Code、Codex、Gemini CLI、Cursor 等等),每个工具配一个专属的像素小人。

![图像](https://pbs.twimg.com/media/HJHCffrbcAARWeo?format=jpg&name=large)

我第一次跑起来,看着像素小哥在我刘海里小跑,挺乐的。乐过之后,作为一个 iOS 工程师的职业病就上来了:**它凭什么能"知道"Claude 在干嘛?**

就是 hooks。

CodeIsland 往每个 AI 工具的配置里,装了一批轻量的 hook。AI 每做一件事,比如开始一个会话、调用一次工具、弹出一个权限请求,对应的 hook 就被触发,把"我现在在干这个"这条消息扔出去。CodeIsland 在另一头接住,刷新刘海上的画面。

你看,这就是开头那个"感应灯"的真实样子:**AI 的动作,变成了可以被钩住的事件**。钩住之后拿来干嘛?做动画也好,记日志也好,拦截也好,都是你的自由。CodeIsland 选了一条最讨喜的路:把它做成你眼前这个可爱的小动画。

(顺嘴一提,CodeIsland 的作者也提到,它的灵感来自另一个叫 claude-island 的项目。一个 idea 被社区接力着越玩越花,这本身就说明 hooks 这个口子开得有多活。)

到这儿,你对 hook"是什么、能干嘛"应该有感觉了。下面拿 Claude Code 当样本,看看它具体长什么样。

## 三、Claude Code:钩子机制最典型的样子

Claude Code 这块做得比较完整。理解它之后,再看别的 agent 里的类似机制,也会顺很多。

一个 hook 的配置,拆开看就三层,顺着读特别好懂:

1. **事件(Event)**:在生命周期的哪个时刻触发?比如会话刚开始的时候、用户刚提交一句话的时候、工具调用之前、工具调用之后、AI 这一轮干完想停的时候。
2. **匹配器(Matcher)**:一个过滤条件,决定"什么情况下才真的触发"。在工具事件里,它通常匹配的是工具名;更细的参数级判断,现在更多会交给 if 规则。比如"只在 AI 想动 Bash 命令时"、"只在写文件时"。
3. **处理器(Handler)**:命中之后,实际跑的那段东西。最常见的就是一段你自己写的脚本。

**事件触发 → 匹配器过滤 → 处理器执行**。就这么一条流水线。数据通过标准输入(stdin)以 JSON 喂给你的脚本,脚本干完活,再通过输出告诉 Claude Code 接下来怎么处理。至于能不能"拦下",取决于这个 hook 挂在哪个事件上。

Claude Code 提供的事件相当多,但你只需要先认得这几个,后面就够用了:

- SessionStart —— 会话开始时
- UserPromptSubmit —— 你刚提交一句话、还没发给模型时
- PostToolUse —— 每次工具调用**之后**
- Stop —— AI 这一轮回答完、准备停下时
- SessionEnd —— 整个会话结束时
- PreToolUse —— 每次工具调用**之前**

这里面,请你特别记住最后这个 **PreToolUse:如果你要拦截一次工具调用,它是最关键的入口,因为它发生在工具真正执行之前。** 想做"保护"、"拦截"、"先问过我再动手"这类事,通常都得挂在它身上。其它事件大多是"事后观察"、"往上下文里塞点东西",或者控制一轮对话能不能继续,但改变不了已经执行过的工具调用。

(处理器除了跑脚本,Claude Code 还支持调 HTTP 接口、甚至再喊一个小模型来帮你做判断。这些进阶玩法这篇先不展开,知道"处理器不止能跑脚本"就行。)

## 四、边界:钩子能干什么,不能干什么

讲到这儿你可能已经有点上头了:"那我岂不是能用 hook 把 AI 管得死死的?"

打住。这里很容易想歪,我自己一开始也想歪过。用两个我自己的真实需求来说。

**第一个需求:我有些核心文档,AI 改了我得知道。**

我们项目里有几份重点文档(架构图、对外协议、一些定下来不轻易改的约定),我不希望 AI 悄没声地改了我还不知道。不是不让它改,是改了得告诉我。这个用 hook 做,很顺、很靠谱:

- 想"改了之后提醒我" —— 挂 PostToolUse,AI 写完文件后,脚本检查改的是不是这几份文档,是就打日志、弹个警告。
- 想"压根不让它改" —— 挂 PreToolUse,AI 一伸手就拦下,直接拒绝,或者降级成"弹出来让我确认一下再放行"。

这类拦"写入" 的活,hook 干得漂亮。因为"写文件"这个动作很明确,入口就那么几个,你守得住。

**第二个需求:我有些敏感文件,根本不想让 AI 读。**

听起来跟上面是一回事,挂个 PreToolUse 拦掉读取不就行了?机制上确实成立,但这里有个坑,恰恰是 hook 的能力边界所在。

你拦住了 Claude 的"读文件"工具,它还能用 Bash 绕:cat secrets.env、grep 一下、tail 一下,甚至写个一行 Python 脚本去读。你要真想堵死,就得连 Bash 命令一起拦,去匹配命令里有没有碰到那些敏感路径。可你一旦开始拦命令,就掉进一场**正则军备竞赛**:cat 堵了还有 less、head、xxd、python -c "open(...)" …… 堵不完的。

所以这里有一条特别重要的认知:**靠 hook 拦读取,本质是"提高门槛",不是"绝对隔离"。**

真想保护敏感文件,hook 是**最后一道**,不是第一道。第一道应该是让 AI 根本接触不到:用权限规则或 sandbox 把读取路径挡住,把敏感信息放进环境变量或密钥管理系统,而不是让它明文躺在项目文件里。忽略规则可以辅助减少上下文暴露,但别把它当安全边界。hook 的角色是兜底:万一它真伸了手,给你拦一下、报个警。

我现在会这么理解:**别把护栏当围墙。** hook 是"提高门槛 + 出事报警",不是"绝对禁止"。能干的它很能干,比如确定性触发、拦写入、留痕、注入上下文;不能干的别硬上。否则你得到的是一种虚假的安全感,那比没有还危险。

想清楚了边界,我们再来看一个把 hook 用到极致的真实案例。

## 五、claude-mem:它是怎么"记住"你的

用过早期 Claude Code 的人多半知道一个痛点:**它没有记性**。这个会话里你跟它磨了半天达成的共识、踩过的坑、定下的约定,关掉窗口,下次再开,它一问三不知,一切从头来过。

年初那会,我自己最离谱的一次,是连续三天每天开新会话,它把之前的项目背景都忘了,我还得从头讲一遍。讲到第三天我自己都烦了,心里一句话冒出来:这事儿就不能它自己记住吗?

claude-mem 这个插件估计很多人都听过,GitHub 上 star 数非常高。

claude-mem 这个插件就是来治这个病的:跨会话的持久记忆。它能"记住"你之前干过什么,下次开新会话时,把相关的上下文悄悄塞回来。

它凭什么能记住?到这里其实答案已经很明显了:**入口和闭环主要靠 hooks**。

claude-mem 几乎把一段会话的完整生命周期都架在了 hook 上,每个事件对应记忆的一个动作:

- SessionStart(会话开始)→ **加载**:从数据库里捞出跟当前工作相关的历史记忆,压缩成一个索引,悄悄注入到这次会话的上下文里。这就是 Claude"想起来了"的那一刻。(顺带说个细节:Claude Code 2.1.0 之后,这个注入是**静默**的,你看不见它往上下文里塞了东西,它走的是一个专门的"附加上下文"通道。)
- UserPromptSubmit(你提交一句话)→ **记意图**:把你这次想干嘛记下来。
- PostToolUse(每次工具调用后)→ **观察**:AI 每读一个文件、跑一条命令、改一段代码,都被记成一条观察。
- Stop(这一轮停下时)→ **总结**:生成这一段的会话摘要 —— 干了什么、学到了什么、下一步该干嘛。
- SessionEnd(会话结束)→ **收尾**:做最后的清理和归档。

加载、记意图、观察、总结、收尾。一段记忆的完整闭环,全是用生命周期事件钉出来的。所以我挺喜欢 claude-mem 这个例子。它不是炫技,只是把 hook 这把"钩子",挂在了记忆该发生的每一个时刻。

一个值得抄进所有 hook 设计的解法

下面这段会稍微工程一点。如果你只想带走结论,先记住一句话就行:**hook 负责接住事件,后台服务负责干重活。**

讲到这儿,要拐进全文最有含金量的一个点了,你可以稍微停一下慢慢读。

前面说过,hook 必须**快**。它卡在 AI 的工作流当中,AI 干完一步要等 hook 放行才能下一步。所以一个 hook 最好在**一秒以内**返回。慢了,整个 AI 就跟着卡顿。

可问题来了:claude-mem 要做的"记忆压缩",是要喊 AI 把一堆原始记录嚼碎、提炼成精华的。这事**要花 5 到 30 秒**。

一边要求"一秒内返回",一边"要花半分钟"。这个矛盾怎么破?

claude-mem 的解法,漂亮得值得你抄进自己所有的 hook 设计里:**hook 本身只做一件极快的事:把要处理的东西塞进一个队列里(几毫秒搞定),然后立刻返回放行。** 真正耗时的 AI 压缩,交给一个在后台常驻的独立服务(worker)去慢慢做。hook 和 worker 一快一慢,彻底解耦。

回头看第二节那个刘海小动画 CodeIsland,它是不是也一样?hook 触发后只做一件极快的事:把一条消息从 socket 发出去,然后立刻返回;真正的渲染、动画、界面更新,全交给那个常驻的 app 去干。

**两个八竿子打不着的应用,一个做记忆,一个做可视化,架构却长得一模一样。** 这不是巧合,是被"hook 必须快"这条铁律逼出来的结果:**很多稍微复杂的 hook 应用,最后都会把自己劈成两半。一个极快的 hook 负责"接住事件、立刻闪人",一个常驻的后台进程负责"慢慢干重活"。**

你以后但凡要写稍微复杂点的 hook,记住这条:**别在 hook 里干重活。hook 只负责把事件接住、扔出去,剩下的交给后台。**

(还有个有意思的坑,顺便讲给好奇的你:你可能以为记忆压缩是在"上下文快满、要清理"的那一刻做的。其实不行。那个时刻太早,压缩出来的摘要还没生成,hook 看不到。所以 claude-mem 是绕了个弯,等下一次会话开始、摘要已经躺在记录里了,再把它捞出来存。工程里这种"理论时刻"和"实际能下手的时刻"对不齐的事,特别多。)

## 六、收个尾

我们从一盏感应灯出发,走到了这里。回头看,hooks 这个机制的内核其实特别朴素:

**它承认了一件事:AI 是不能完全信任的。** 所以真正重要的约束,不能只写在你跟它说的话里(它可能不听),还得放进工具链和运行环境里,让系统替你执行。

而一旦你能在它生命周期的很多关键时刻钉上一个钩子,这个原本黑箱、健忘、偶尔不听话的 AI,至少会变得更容易观察,也更容易约束。CodeIsland 把它的一举一动画在了你眼前;claude-mem 把它的经历存了下来;PreToolUse 则让你有机会在它动手前先插一脚。

这背后是一个我一直信奉的次序:**先让它可观测,再谈约束它,最后才轮到自动化。** 顺序错了,你建起来的不是护栏,是幻觉。

如果只带走三件事,我会选这三条:

1. **hook 是挂在 agent 生命周期里的自动动作**。某个事件发生了,它就会触发。
2. **PreToolUse 适合拦工具调用,PostToolUse 适合记录和观察**。一个管事前,一个管事后。
3. **hook 不是安全沙箱**。敏感文件要靠权限规则、sandbox、密钥管理先挡住;复杂任务要交给后台服务慢慢做。

如果你也想开始用 hook,可以先做这几件事:

1. **把核心文档的 PreToolUse 拦截先挂上**。这是收益最高、成本最低的一条,先吃下来。
2. **敏感文件走权限规则、sandbox 和密钥管理,hook 只做兜底**。别再幻想用 hook 把读取堵死。
3. **写自己的 hook 时,凡是预计超过 1 秒的活,一律拆成"hook 收事件 + 后台跑重活"**。claude-mem 和 CodeIsland 已经把答案写在那儿了,照抄就行。

最后留个钩子:claude-mem 这套漂亮的记忆机制,是为 Claude Code 生态做的。但如果你用的不是 Claude Code,而是别的 agent —— 比如腾讯的 CodeBuddy —— 它能不能也用上这套记忆能力?

我把它适配过了,中间踩了几个挺有意思的坑,也打算把成果开源出来。这个,后续有机会再开一章。
