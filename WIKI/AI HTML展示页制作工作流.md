# AI HTML展示页制作工作流

> [!abstract]- AI 摘要
> 将 AI 生成的 UI 设计图转化为高质量 HTML 展示页的系统化方法，核心是拆开结构、样式、资产三层分别处理，通过反复的截图-对比-修正循环逼近像素级还原。

---

## 扫读

> [!tip] 💡 一句话
> AI 写 HTML 翻车的根源不在模型能力，而在任务没拆开——把代码和视觉资产搅在一起让模型硬画，结果必然廉价。

> [!important] 📌 关键结论
> - UI 还原必须拆成三层：结构（HTML/CSS）、样式（字体/颜色/间距）、资产（logo/插画/产品图），混合处理是翻车主因
> - 资产分离的判断标准：拿掉该元素后页面结构是否还成立？成立是资产，不成立是结构
> - 绿幕抠图法（Python PIL 逐像素判定）是处理不支持 alpha 通道的第三方生图渠道的实用方案
> - 六步工作流：视觉拆解 -> 资产分离 -> HTML 骨架 -> 生成替换资产 -> 浏览器截图 -> 对比修正
> - 复现不像时不应重写，应先归类到六类误差之一：布局、字体、色彩、资产、密度、响应式

> [!quote] 🎬 可行动项
> - 下次做 HTML 还原前，先让 AI 输出一份"页面地图"而非直接写代码
> - 建立个人的 Playwright 截图 + 并排对比的验证流程，把质量从一次性生成变为迭代收敛

## 精读

### 论证链

```
直接让 AI 根据 UI 设计图生成 HTML，实际是同时要求它完成三类不同任务（识别结构、复刻样式、生成资产），模型在生成复杂视觉资产（插画、logo 等）时容易将 CSS/SVG 拼凑出形似但廉价的替代品
↓
正确做法是任务分层：先让 AI 做视觉拆解输出页面地图，再将元素分为"代码负责"和"图片负责"两类
↓
分两类按不同管线处理：HTML/CSS 负责布局骨架，视觉资产走"裁参考图 -> 图生图重画 -> 透明底处理（alpha 通道或绿幕抠图）"的单独流程
↓
骨架搭好后用 Playwright 在真实浏览器中截图，与原始设计稿并排对比，逐区域定位差异
↓
差异不靠感觉判断，按六类误差体系归类定位：布局/字体/色彩/资产/密度/响应式，每类有明确的调整方向
↓
反复截图-对比-修正循环，"后验机制才是质量来源"，不要把 UI 还原当成一次性生成任务，是误差收敛过程
```

### 关键引述

> UI 还原要拆成三层看：结构、样式、资产。结构和样式交给 HTML/CSS。logo、插画、产品图、3D 视觉这类东西，单独当成图片资产处理。

> 判断一个元素该不该做成资产，有个简单办法：把它拿掉以后，页面结构还成立吗？logo 拿掉，导航栏还是导航栏。插画拿掉，空状态容器还是空状态容器。它们是贴上去的视觉层，不属于页面骨架本身。

> 廉价感通常来自字重、间距、密度和资产质量。这几样需要人盯。你不指出来，它可能会觉得已经差不多了。

### 局限与盲区

- 本文未覆盖：多页面网站的导航一致性和组件复用策略、移动端和多分辨率适配的详细方法论、动画/交互效果的 AI 还原方案、SEO 和可访问性等生产环境需求、团队协作中设计稿版本管理的流程
- 隐含假设：设计稿本身质量过关（AI 出的图本身没问题），但如果设计稿本身存在不合理布局，还原的再准也是低质量页面；Playwright 截图对比依赖人工判断误差类型，自动化对比的量化标准未讨论
- 可能的反例：对于高度依赖复杂 CSS 动画和交互的场景（如游戏化页面），资产分离策略可能不足以解决质量问题；绿幕抠图对边缘复杂（如头发丝、半透明区域）的资产效果较差，可能需要更专业的图像处理工具
