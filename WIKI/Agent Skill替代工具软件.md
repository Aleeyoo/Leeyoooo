# Agent Skill替代工具软件

> [!abstract]- AI 摘要
> 一个开源磁盘清理 Skill 替代了年费 120 美元的 CleanMyMac——不仅免费，而且更透明、更灵活、更个性化。这不是孤例：解压缩、PDF 编辑、图片格式转换等所有"执行明确规则可定义任务"的传统工具软件，正在从"软件资产"变成"Agent可即时生成的耗材"。

## 扫读

> [!tip] 💡 一句话
> 那些靠一个明确功能养活团队的工具软件，现在面对的不再是另一家软件公司的竞争，而是用户手里的一条 prompt 和一个 Agent Skill——软件的本质是人和机器之间的翻译层，Agent 正在填平这道鸿沟。

> [!important] 📌 关键结论
> - 磁盘清理 Skill 对比 CleanMyMac（120 美元/买断）：Agent 扫描更全面（发现 97GB B站离线缓存 vs CleanMyMac 仅发现 15.8GB 传统垃圾）、信息更透明（每项含具体路径、大小、删除影响说明 vs "用户缓存文件-可删"）、可个性化（大白话说"找某种文件"即可 vs 写死规则）
> - Skill 的核心设计是三色安全分级：绿灯（纯缓存/临时文件/安装包残留，Agent 可直接清理，有二次确认）、黄灯（需人看一眼再决定，如离线视频/下载文件夹）、红灯（系统文件/正在使用的核心数据，只解释不动手，但提供访达快捷入口）
> - 深层判断：软件正在从"资产"变成"耗材"——一个解压缩、PDF 编辑、图片格式转换的需求不再需要安装专用软件，而是一条 prompt 和对应的 Agent Skill。这些工具的共同特征是执行"相对明确、规则可定义的任务"——恰恰是 Agent 最擅长的事

> [!quote] 🎬 可行动项
> - 检查自己电脑上的工具类软件清单（解压、格式转换、重复查找、系统清理），尝试用一个 prompt 或 Skill 替代其中至少一个，对比体验
> - 设计 Agent Skill 时加入分级安全策略：明确区分"可直接自动执行""需用户确认""绝对不可操作"三个等级，并给每级设计不同的交互模式
> - 思考自己的专业领域：哪些工作流是"规则可定义的任务"——Agent Skill 化的机会就在那里

### 论证链

```
触发事件：X 上一条 prompt → "do a FULL read only analysis on my Macbook"
  发现 500GB 可清理空间 + 116GB codex-tui.log 文件
        ↓
作者实践：将 prompt 扩展为完整 Skill
  动机：九年想买 CleanMyMac 但买不起→如今用 Agent 圆梦
        ↓
Skill 输出：可交互 HTML 报告，四部分结构：
  ① 磁盘总览：容量/使用/剩余 + 彩色进度条 + 系统环境扫描
  ② Top 5 占用排行：颜色标签 + 类型 + 完整路径 + 一句话说明
  ③ 执行建议：按性价比排优先级（清离线视频 > 纯缓存命令 > 其他）
  ④ 三色分级详情区（核心）：
     🟢 绿灯：纯缓存/临时文件/安装包残留→Agent可直接清理
        展开后：路径+清理前关进程提示+清理命令(可复制)+移到废纸篓/直接删除按钮
        → 按钮触发二次确认弹窗 → 执行后网页实时更新为"已清理"
        → 右上角一键清理所有绿灯项
     🟡 黄灯：需人看一眼（B站视频/下载安装包/项目文件夹）
        告知是什么、为什么建议看、删了有什么影响 → 自己在访达（Finder）里决定
        有安全子路径的额外给"移到废纸篓"选项（可逆）
        比如：B站视频文件夹→仅清理视频保留登录态和设置
     🔴 红灯：系统文件/应用核心数据/sleepimage
        解释为什么不能动 → 跳过清理，但提供在访达中打开
  ⑤ 长期优化建议
        ↓
安全设计：扫描阶段全程只读禁止写操作，只有用户主动点击按钮+弹出确认+再确认后才执行
        ↓
对比 CleanMyMac：
  CleanMyMac：扫 30 分钟→15.8GB 垃圾→"用户缓存文件-可删"→信息不足以做决策
  Agent Skill：几分钟→约 120GB→每项路径/大小/影响说明→三色分级+可定制
  关键差异：Agent 能"读文件内容"而非仅扫描文件类型→发现非传统垃圾（B站缓存）
        ↓
更广泛的意义：
  软件的本质 = 人和机器之间的翻译层
  Agent 正在填平这道鸿沟
  工具软件的定义特征 = 执行明确、规则可定义的任务 → Agent 的舒适区
  竞争对手不再是另一家软件公司 → 是用户的 prompt 和 skill
  软件从资产变成耗材：需要时生成，用完即弃
```

### 局限与盲区

- 本文未覆盖：Skill 在不同操作系统（macOS vs Windows vs Linux）上的兼容性和稳定性测试细节；Agent 操作文件系统的安全边界——虽然作者强调"全程只读+二次确认"，但删除操作一旦执行错误后果不可逆（特别是"直接删除"选项），skill 的可信度依赖于 Agent 底层模型对文件类型的判断准确率；Skill 在不同 Agent 平台（Codex、Claude Code、Cline）上的移植成本
- 隐含假设：用户有能力判断三色分级中的"黄灯"项是否真正需要保留——对于非技术用户，即使有详细说明也可能无法做出正确决策；假设文件扫描和分析的准确率已达到生产可用水平，但实际中 Agent 的幻觉可能将系统关键文件错误分类；假设用户愿意在浏览器而非本地应用中完成系统级操作，这涉及使用习惯改变
- 可能的反例：专业软件的价值不仅是功能本身，还包括长期积累的边缘 case 处理、用户体验打磨、客服支持和法律责任承担——这些是单个 Skill 难以替代的；某些工具软件（如 Photoshop、AutoCAD）的功能复杂度远超"规则可定义任务"范畴，不会被简单 Skill 威胁；Skill 作为"软件耗材"的前提是 Agent 平台（Codex/Claude Code）持续存在且接口稳定——这是平台依赖风险
