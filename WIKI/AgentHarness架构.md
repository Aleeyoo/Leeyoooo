# AgentHarness架构

> [!abstract]- AI 摘要
> 深度拆解 AI Agent Harness 的 12 个核心组件：从编排循环、工具、记忆、上下文管理到提示词构建、错误处理、护栏和子智能体编排。Harness 是让 LLM 从"无状态模型"变成"全能 Agent"的完整软件架构。

## 扫读

> [!tip] 💡 一句话
> 如果你不是模型本身，那你就是 Harness。两个使用相同模型的 Agent 性能天差地别，原因全在 Harness 的设计。

> [!important] 📌 关键结论
> - Harness 是包裹在 LLM 外的完整软件架构，包含 12 个组件：编排循环、工具、记忆、上下文管理、提示词构建、输出解析、状态管理、错误处理、护栏、验证循环、子智能体编排和生命周期管理。
> - 核心设计原则：上下文是稀缺资源（找到信号最强的最小 Token 集合）、权限执行与模型推理必须分离、验证循环是区分"玩具"和"生产级"的关键。
> - 随着模型能力提升，Harness 会变薄但不会消失。协同进化原则：好的 Harness 设计能在模型升级时自动获得性能提升。

> [!quote] 🎬 可行动项
> - 检查你的 Agent 的上下文管理策略：是否在接近限制时主动压缩？是否用子 Agent 委托替代加载大段文件？
> - 为 Agent 加入验证循环：基于规则的测试反馈、LLM-as-judge 评估输出
> - 实现权限与推理分离：Agent 可以提议做什么，但 Harness 决定允许做什么

### 关键引述

> "如果你不是模型本身，那你就是 Harness。"

> "原生大语言模型就像一个没有内存、没有硬盘、也没有输入输出设备的 CPU。上下文窗口充当了内存，外部数据库扮演了硬盘，工具集成是设备驱动程序。而 Harness，就是那个操作系统。"
