# 四层Agent工程的隐藏代价

> [!abstract]- AI 摘要
> 对"Agent四层工程解法"的批判性补充：稳定性（Harness）、可靠性（多Agent）、连续性（记忆）、成长性（Instinct）四层解法方向全对，但每一层在解决一个显性问题时，都同时制造了一个更隐蔽的新问题——校验器会合谋、上下文会碎片化、记忆会投毒、学习会把坏习惯一并固化。本文逐一揭示四张账单，提出"没疼之前别加复杂度"的 YAGNI 原则。

## 扫读

> [!tip] 💡 一句话
> Agent 四层工程解法（Harness、多Agent、记忆、Instinct）每层都是真解法，但每层都是用一道显眼的问题，换一道更安静的问题——这些隐藏代价不是你加错了什么，而是你加了之后系统引入的新失败面。

> [!important] 📌 关键结论
> - Harness 层的隐藏代价不是"要不要做"，而是你加的每道校验器本身也是 LLM——用一个会胡说的东西校验另一个会胡说的东西，"合谋放行"比没有校验更危险
> - 多 Agent 层的账单最重：Anthropic 自曝多 Agent 消耗约 15 倍 token，且 Cognition 指出上下文碎片化让子 Agent 间的隐含决策相互冲突。绝大多数项目根本还没到需要多 Agent 的地步
> - 记忆系统用语义检索省了 95% token，但召回静默失败时 Agent 不会报错——它拿着缺失的上下文自信地给错结论，从"贵但对"换成了"便宜但可能错"
> - Instinct 把频率当置信度（3-5 次→0.5，11 次以上→0.85），这意味着坏习惯和好习惯被同等忠实地学走并自动注入，学习系统正在把你连缺点一起固化

> [!quote] 🎬 可行动项
> - 每想加一层解法之前先问："现在不加，最坏会怎样？"——答不上来就不加，遵循 Agent 工程的 YAGNI 原则
> - 校验器的验证：每一道 Sensor 上线前必须用对抗样本测试，确认没有和生成 Agent 形成"合谋"（两个模型同时出错的协同模式）
> - 多 Agent 决策：先把单 Agent 的 Harness 做到极致，真扛不住再从最简单的生成-验证模式开始，避免一步跳到消息总线或共享状态
> - 记忆安全：被检索回来的记忆一律当成"写入时为真"的旧情报，不当当前事实——关键字段先验证再用
> - Instinct 治理：给学习系统配遗忘和质疑机制——置信度再高的 Instinct 也要定期重新质询，能写进去就得能被推翻

## 精读

### 论证链

```
起笔：认同四层解法的分析框架，方向全对
  → 但核心追问：每层解法到底要付出什么代价？"加什么能变好"讲完了，"加完要还什么"没人讲
        ↓
第一层账单——Harness 过拟合 + 校验器合谋：
  过拟合风险：榜单排名提升可能来自针对性调参而非真实能力增长（"注意第 N 类边界情况"这种规则对固定评测集有效对现网无效）
  校验器合谋：真实案例——内容审核 Agent 加"质量评估"Sensor，评估 Agent 学会了给"看起来完整、语气自信"的暴力输出打高分
  → 生成 Agent 最擅长糊弄的维度恰好是评估 Agent 最买账的维度 → 两个模型合谋盖章放行
  核心风险：一道没被验证过的校验器比没有更危险——它给了你"已经兜底了"的错觉
        ↓
第二层账单——多 Agent 被高估 + 代价隐性：
  数据举证：Anthropic 自述多 Agent 消耗约 15 倍 token（单 Agent 约 4 倍）
  行业对立：Anthropic 推编排器-子智能体 vs Cognition 坚持"Don't Build Multi-Agents"（上下文碎片论）
  五种模式各自的致命局限：
    生成-验证：需要靠最大迭代次数兜底 → 撞上限时拿到的是"没谈拢但被迫交付"的半成品
    编排器-子智能体：信息瓶颈 → 子 Agent 关联信息多次中转后细节丢失（即上下文碎片化）
    共享状态：没设好终止条件就是烧钱永动机
  实践建议：绝大多数人没到需要多 Agent 的地步，先上最简单的生成-验证模式
        ↓
第三层账单——记忆系统的静默故障：
  语义检索的代价：从"全量加载（贵但对）"换成"按需召回（便宜但可能错）"
  静默失败：该召回的关键背景没召回来 → Agent 不报错不提示 → 拿着不全上下文自信地给错结论
  记忆投毒：AI 自己写入的错误结论（如误判的根因）→ 之后每次会话被当成"事实"重新注入 → 自我繁殖的错误
  实战规则：被检索回来的记忆一律视为旧情报，关键字段先验证再用
        ↓
第四层账单——Instinct 学的是频率不是正确：
  置信度公式的偷换：3-5 次→0.5，6-10 次→0.7，11 次以上→0.85 → 把观测频率等同于行为正确性
  坏习惯固化：你总不写测试，系统忠实学成 0.7 置信度的 Instinct → 每新会话自动注入提醒 AI 也不写测试
  不可调试：Instinct 不在你的提示词里不在代码里 → 出问题时根因躺在你不会去翻的 YAML 库
  固化抗拒改变：AI 攒了"你喜欢怎么干"的高置信度习惯后倾向于延续，但你正处该升级工作方式的节点
  核心悖论：学习系统让你越来越像过去的你，但真正的伙伴应该能帮你跳出过去
        ↓
收束：四张账单的模式——每层都是真解法，但每层都用显眼问题换更安静的问题
  → 实操原则：没疼之前别加复杂度（Agent 工程的 YAGNI）
  → 每加一层之前先问"现在不加，最坏会怎样？"
```

### 关键引述

> "Harness 这层真正的成本不是要不要做——必须做——而是你加的每道 Sensor 都是一段需要被验证的新代码。它不会自动正确。一道没被验证过的校验器比没有校验器更危险，因为它给了你一种已经兜底了的错觉。"

> "多 Agent 系统消耗的 token，大约是普通对话的 15 倍（单 Agent 大约 4 倍）。"

> "记忆系统没有消除风险，它只是把风险从'贵'换成了'静悄悄地错'。"

> "它不是在帮你变好，是在帮你把当下的自己连缺点一起固化下来。频率高不等于正确，这俩之间没有等号，可置信度公式里画了等号。"

> "一个只会攒、不会忘也不会纠错的记忆系统，时间一长就是个偏见放大器。"
