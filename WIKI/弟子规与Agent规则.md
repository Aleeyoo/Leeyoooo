# 弟子规与Agent规则

> [!abstract]- AI 摘要
> 《弟子规》1080 字 43 个"勿"，与 GitHub 上 AGENTS.md 的"Never do X"共享相同的规则语法。禁令比正面引导更有效，但仅有服从没有询问机制是危险的——Agent 需要"Ask first"层。

## 扫读

> [!tip] 💡 一句话
> 《弟子规》和 AGENTS.md 本质上是对同一个问题的回答：在无穷多种可能的行为中，划掉几条会出大事的。

> [!important] 📌 关键结论
> - 正面引导需要解释"怎么做得好"（无数种方式），反面禁令只需列出红线（少数几条），工程上禁令效率远高于引导
> - 三级边界系统（Always / Ask first / Never）比"勿"更完整——Never 是护栏，Ask first 是让 Agent 在关键决策前停下来问
> - "不力行，但学文，长浮华"对应 Agent 规则设计：规则不是先背会的，是在行动中碰撞出来的——先撞出风险，才知道哪些事要写成"勿"

> [!quote] 🎬 可行动项
> - 写 Agent 规则时优先定义 Never（红线），然后补充 Ask first（需要询问的操作），最后再考虑 Always（常规行为）
> - 每一条 Never 规则都应该来自过往事故——不是凭空设计边界，而是复盘后添加护栏

## 精读

### 论证链

```
《弟子规》：1080 字，43 个"勿"
AGENTS.md：2500+ GitHub 项目，"Never commit secrets" 出现频率最高
      ↓
共同语法：禁令 > 正面引导
      ↓
原因：正面引导需描述"做得好"（无限种方式，需场景/角色/风格）
反面禁令只需列出红线（少数几条）→ 信息密度极高
      ↓
机制：
① Always：Agent 不需要问就可以做的事（跑测试、遵守命名规范）
② Ask first：做之前必须先问（改数据库 schema、改 CI 配置、删测试）
③ Never：红线，触发即停止（密钥、生产数据、隐私信息）
      ↓
规则来源：先有行为，才有边界
先撞出风险，才知道哪些事要写成"勿"
《余力学文》放在最后绝非偶然
      ↓
结论：《弟子规》的"勿"是正面启示，但其"挞无怨"的服从逻辑是反面教训
Agent 需要的是"会询问的智能"，不是"听话机器"
```

### 关键引述

> 清朝那位秀才，跟 2025 年那个写 AGENTS.md 的工程师，本质上面对的是同一个问题：在无穷多种可能的行为里，划掉几条会出大事酿大错的。

> 规则不是先被背会的，规则是在行动里碰撞出来的。一份好的 AGENTS.md，应该是事故复盘之后留下来的护栏。

> 划好红线，是为了让主体在边界内行动。只训服从，是为了让它在你不在场的时候也别出错。前者更接近 alignment（价值对齐），后者更接近 obedience（命令执行）。
