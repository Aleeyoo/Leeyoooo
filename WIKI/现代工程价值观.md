# 现代工程价值观

> [!abstract]- AI 摘要
> 当代码生成不再是瓶颈，工程价值观必须从"怎么写代码"转向"怎么指挥系统产出代码"。cpojer 提出 Agent 时代的 6 条工程价值观：强所有权、品味、严格护栏+快速反馈、上下文放在仓库里、掌控技术栈、保留选择权。

## 扫读

> [!tip] 💡 一句话
> 编程不再瓶颈后，工程价值从"产出代码"转移到"判断该产出什么、如何验证"——小型团队+强所有权+仓库内集中上下文+严格自动化护栏是最有效的 Agent 时代工程模式。

> [!important] 📌 关键结论
> - 代码生成的成本被压到地板，瓶颈从写代码转移到验证、代码评审、安全——旧流程（瀑布规划、多人 code review、角色边界）正在失效
> - 六条现代工程价值观：(1) Strong Ownership 强所有权——小团队（2-3人）+隔离仓库+直接推主分支；(2) Taste 品味——决定什么值得做比怎么做更重要；(3) 严格护栏+快速反馈循环——lint/测试/自动化验证让 Agent 从 60 分钟收敛到 1 分钟；(4) Context in Repo 仓库内上下文——所有上下文集中放仓库而非分散在 Notion/人脑中；(5) Own Your Stack 掌控技术栈——Agent 时代不应再把核心能力外包给第三方依赖；(6) Option Value 保留选择权——每次变更都应解锁更多未来可能性
> - 管理层必须技术化：Tech Lead Management 是唯一正确的管理角色——管理者必须保持领域专长、能自信做出变更、提供技术领导力
> - 实测数据：Agent 辅助下日均出货量从 5K 行升至 15K 行（3x），commits 从 328 升至 770（2.3x），且质量更高

> [!quote] 🎬 可行动项
> - 审计代码库的上下文分布：所有 Agent 需要的上下文是否集中在仓库中（AGENTS.md + docs/）而非分散在 Notion/Google Docs/人脑中
> - 建立严格护栏：lint rules + automated testing + fast verification pipeline，目标是让 Agent 的反馈循环从 60 分钟缩到 1 分钟
> - 重新评估每个第三方依赖：Agent 降低了自研成本，核心产品逻辑是否还值得外包给外部库
> - 将 Code Review 重心从风格/语法检查（交给 Agent）转向架构对齐和品味判断（保留给人）

## 精读

### 论证链

```
作者亲身实验：5 个产品 90%-100% AI 写代码，质量等同或超过手写
  → Athena Crisis（手写代码库）：70+ bug 修复 + 新功能 + 测试，全由 Agent 循环完成
  → 日均代码修改量从 ~5K 行（2024）升至 ~15K 行（2026），commits 从 328 升至 770
        ↓
核心判断：编程不再是瓶颈 → 瓶颈转移到验证/评审/安全
  → 旧流程围绕"写代码很贵"设计（瀑布规划、层层评审、严格分工）
  → 新瓶颈下旧流程全部失效
        ↓
六条现代工程价值观：
  ① Strong Ownership：Agent 像新员工，有领域专长的人能快速执行，没上下文的人只能制造噪音
     → 小团队（2-3人）+ 清晰所有权边界 + 隔离仓库是最佳组织形态
     → Code review 聚焦对齐而非代码争论
  ② Taste：Agent 能生成大量 bullshit → 品味决定了什么值得花时间
  ③ Strict Guardrails & Fast Feedback Loops：越多约束（lint/测试/自动验证）= Agent 越快收敛
     → 护栏和反馈速度是 Agent 1 分钟完成 vs 60 分钟完成的区别
  ④ Context in Repo：Agent session 像新员工，没权限访问 Notion/Docs/人脑
     → 把所有相关上下文集中放在仓库中，同时让代码对人类和 Agent 都可读
  ⑤ Own Your Stack：以前 95% 代码是第三方依赖因为写代码贵
     → Agent 改变了成本因子 → 核心部分应该自研以保持完全控制
  ⑥ Option Value：大改动变便宜了，但 vibe coding 可能把你带进死胡同
     → 每一次变更都要考虑是否解锁更多未来可能性
        ↓
管理变革：中层管理者必须保持技术深度
  → Tech Lead Management = 保持领域专长 + 能自信变更 + 提供技术领导力
  → 纯粹管人管进度的管理模式在 Agent 时代失效
```

### 局限与盲区

- 本文未覆盖：单人开发者/极小型团队的视角——作者管理的多项目并行模式（3-6个项目同时推进）在单一产品公司是否适用；安全关键系统（医疗、航空）中"不看代码直接 ship"的边界在哪里；非英语/非 JavaScript 生态中的 Agent 有效性差异
- 隐含假设：Codex（GPT 5.5）在作者的技术栈和代码风格上表现优秀，但不同技术栈的 Agent 效果可能差异显著；假设团队有足够工程能力维护自研栈的护栏和工具链——小型团队可能负担不起；假设 Agent 输出质量一致——实际上不同任务类型、不同模型的输出质量波动很大
- 可能的反例：过度自研栈（Own Your Stack）在大团队中可能造成 NIH（Not Invented Here）问题和维护负担；"直接推 main"在大规模多团队协作中可能导致集成灾难；Taste 作为价值观高度主观且难以在团队中标准化
