# 编排税即你

> [!abstract]- AI 摘要
> AI Agent 可以无限并行启动，但人的判断力无法并行——你就是系统中的单线程瓶颈。编排税（Orchestration Tax）是你为"忘记这一点"付出的结构性代价。

---

## 扫读

> [!tip] 💡 一句话
> 启动 20 个 Agent 不等于 20 倍的产出，人的判断力是串行瓶颈，Agent 越多，排队等待你审阅的工作越多。

> [!important] 📌 关键结论
> - Amdahl 定律直接适用于 Agent 开发：串行部分（人的判断）决定了系统吞吐量上限，增加并行部分只是加深等待队列
> - "感觉很忙"和"真正产出"是解耦的——24 个 Agent 同时运行让你误以为很高效，但合并到 main 的代码才是真正度量
> - 编排税不付显性价格，就会以隐性方式兑现：浅层审阅、认知投降（认知投降是你直接接受 Agent 代码因为懒得自己想了）

> [!quote] 🎬 可行动项
> - Agent 并行数不应超过你的审阅能力（通常是个位数），而非 UI 允许的数量
> - 区分"隔离任务"（可异步委托）和"复杂任务"（判断本身就是工作，不能并行）
> - 批量审阅：一次审 4 个 Agent 比分散检查省得多

## 精读

### 论证链

```
启动 Agent 的成本极低（一句话）
      ↓
但收尾的成本极高（审阅、合并、冲突解决）
      ↓
人的判断力必须串行执行
你是 Agent 系统的 GIL (Global Interpreter Lock)
      ↓
Amdahl 定律：加速比 ≤ 1/(串行比例)
      ↓
串行比例（审阅）不变 → 加 Agent 只增加队列深度
优化非瓶颈部分（Agent 速度）不增加吞吐量
      ↓
机制：
① 每次切换 Agent 等于上下文冷重启（CPU 用微秒，人用分钟）
② 5 个 Agent ≠ 1x工作×5，而是 5 次冷重启 + 背景焦虑
③ 持续高负载导致认知投降——放弃形成自己的判断
      ↓
结论：你的注意力是稀缺的串行资源，必须像设计分布式系统一样设计它的使用
```

### 关键引述

> You are the GIL of your AI agents. They all can run at once. But when any of their work needs genuine understanding of the architecture or resolving merge conflicts, that work has to acquire the lock. There is one lock. You hold it.

> The orchestration tax is the structural gap between agent production and what you can actually merge. It's what happens when you put a single-threaded resource in charge of a concurrent one.

> Spawning agents is not the skill. Anyone can run 20. The real skill is designing the system around the one serial resource that cannot be cloned or paralellized.

### 局限与盲区

- 本文未覆盖：团队协作场景——当多人共同审阅 Agent 输出时，"锁"不再是单线程，如何分配审阅责任？
- 隐含假设：假设"人的判断"必须在每一步介入。存在一个阈值使 Agent 仅需最终审阅而非逐步介入（如 Stripe Minions 的无人值守模式），此时编排税大幅降低
- 可能的反例：对于低风险、高重复性的任务（如格式化代码、生成测试），人的审阅可以被自动化验证取代，编排税实际为零
