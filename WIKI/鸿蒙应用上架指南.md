# 鸿蒙应用上架指南

> [!abstract]- AI 摘要
> 从开发环境到提交审核的鸿蒙应用完整上架说明书，把包类型、签名、隐私声明等高概念拆解为可操作的步骤，附带提交前清单防止审核返工。

---

## 扫读

> [!tip] 💡 一句话
> 鸿蒙上架的最大陷阱是把"开发完成"当成"发布完成"——代码能跑只是起点，包、签名、隐私、资质对不上才是真正的关卡。

> [!important] 📌 关键结论
> - 上架前必须理解的核心概念链：DevEco Studio（开发工作台）-> AGC（发布后台）-> 包类型（HAP/HAR/HSP/.app）-> 签名（数字证书+Profile+指纹）-> 隐私声明（应用行为+政策正文+AGC 标签三者一致）
> - 包名是应用在系统和平台中的身份证，AGC 创建应用时填的包名必须与工程包名一致，大多数"服务调用失败"的根本原因是包名或 APP ID 对不上
> - 调试签名 != 发布签名，本地能跑不等于能上架，这是新手跳过最多的问题
> - 审核不通过的常见根因：包名不一致、签名配错、隐私政策与应用实际行为不对应、审核人员无法进入核心功能、截图与功能描述不符
> - 上架十步顺序：装 DevEco Studio -> 配 SDK -> 新建工程 -> 跑通模拟器 -> 理解工程结构 -> 构建发布包 -> 配签名 -> 上传 AGC -> 上架前体检 -> 提交审核

> [!quote] 🎬 可行动项
> - 提交审核前逐项核对提交前清单（17 条），优先检查包名一致性、签名信息和隐私材料三方对齐
> - 首次上架建议先用 AppAnalyzer 或云测试跑一轮，避免因崩溃/黑屏等低级问题被打回

## 精读

### 论证链

```
鸿蒙开发者常犯的错误：写完代码就直接去提交审核，忽略了包类型、签名、包名一致性、隐私声明、审核体验等前置条件
↓
必须先建立概念体系：
开发环境层（DevEco Studio, ArkTS/ArkUI, SDK, 模拟器/真机）
↓
工程结构层（Stage 模型, UIAbility=门+页面=房间, Module 是功能单元非包）
↓
构建产物层（HAP=模块小包, HAR=公共工具箱, HSP=共享零件包, .app=最终提交大包）
↓
发布管理层（AGC 创建项目->创建应用->包名/签名/版本号对齐->上传检测->信息填写->隐私核对）
↓
然后按真实上架顺序操作：确认本地工程 -> 注册开发者账号 -> AGC 创建项目和应用 -> DevEco Studio 构建发布包 -> 配置签名 -> 上传 AGC 检测 -> 填写应用信息 -> 隐私核对 -> 提交审核
↓
提交前 17 条清单逐项扫过，核心原则：用户安装到的应用，与你提交的说明、权限、资质是否"同一个东西"
```

### 关键引述

> 鸿蒙应用上架，最怕把"开发完成"当成"发布完成"。代码写完，只是你手里有了应用。能不能上架，还要看包、签名、说明、隐私、资质、测试结果能不能对上。

> 本地能跑，就以为签名没问题；调试能跑，就以为发布也没问题。调试签名和发布上架不是一回事。

> 不要只看"构建成功"四个字。构建成功只能说明包打出来了，不代表它适合上架。能不能安装、能不能启动、核心流程能不能走完，才是上架前真正要确认的事。

> 审核看的东西很朴素：用户下载安装到的这个应用，和你提交上来的说明、权限、资质、质量表现，是不是同一个东西。能对上，流程会顺很多。对不上，再小的问题也会变成返工。
